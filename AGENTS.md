# KCS Dispatch System — confirmed standing requirements

These requirements were confirmed by KC on 2026-09-09. Carry them forward for later work.

- Before implementing a new system change, restate the requested behavior in plain Chinese and wait for KC to confirm the interpretation. After confirmation, proceed with that scope without asking again. The supervisor overview and desktop/mobile language work in this change are already confirmed.
- Supervisors enter the management interface at Overview (总览), not the last-used dispatch page. Keep normal navigation usable after entry.
- Desktop and employee mobile interfaces must support complete English, Bahasa Melayu and Chinese. The selected language applies to pages, cards, buttons, dropdown labels/options, dialogs, tooltips, validation/errors and success notices. Translate display labels, never API enum values or stored business data.
- Preserve official customer, branch, employee, vehicle, route, area and place names. Address/place data remains in English or Bahasa Melayu; do not translate it into Chinese.
- Data-backed dropdowns must read current master records instead of hard-coded option lists. New saved routes, customers, branches, vehicles, staff and areas appear in relevant selectors, subject to permissions and eligibility. Renames refresh the display. Inactive records are unavailable for new assignments while historical references remain intact.
- This document records development requirements, not a claim that every legacy screen already complies. When changing a screen, verify its affected controls against these rules and report remaining limitations honestly.

- All existing and future photo entry points must use the shared in-page camera: live capture, preview before explicit submission, retake/remove, gallery selection, compression, and retained pending photos on upload failure. Camera buttons and notices support en/ms/zh. Preserve PDF document uploads alongside photo controls. This applies to mobile/office expenses, GPS, weighing, payment/No Goods proofs, employee documents and vehicle records. KC confirmed this scope on 2026-09-09.

- KC confirmed a route-order trial for 2026-09-10 through 2026-09-23 inclusive (Asia/Kuching). Assigned drivers/crew can reorder untouched stops within their running trip; the server disables this exception from 2026-09-24. Retain arrival, bill, completion and pending supervisor-approval protections. Employees may request a future collection date; only supervisors approve it and select the target route. Preserve original records and fixed recurrence, prevent duplicate branch/date stops, and audit requests, decisions and trial order changes.

- KC confirmed a single Employee & Account workspace, with Current and Former employee groups (default Current). Expand the complete employee and login editor directly below the selected name; retain the viewport-bottom horizontal scrollbar. Create an optional login together with a new employee atomically. Keep employment and account state distinct: departure immediately disables login and revokes all existing sessions while preserving history. An account cannot be reactivated while the employee remains departed; rehire is an explicit process.

- Expenses: desktop and mobile share vehicle, odometer km, invoice/reference, merchant company, TIN and remarks fields. Fuel, Services, Repair, Spare Parts, Road Tax, Puspakom and Insurance require all except TIN/remarks. All categories, including Other, require merchant company and invoice/reference, displayed below Other description and outside Receipt details. Other permits blank extra description, vehicle, odometer, TIN and remarks; amount and receipt photo remain required. Receipt OCR fills only empty fields and requires user review before saving; never guess missing values or overwrite manual entries. Preserve original proof and manual entry on recognition failure.

- Every Expenses and Purchase Bill Records column menu supports checkbox multi-selection, Select all, Blank, ascending/descending and clearing filters/sort. Dates sort chronologically, amounts numerically, and names/identifiers naturally (A–Z, embedded numbers). Export uses the same filters/order as the displayed archive.

- Purchase Bill Void: mobile More and desktop beside Purchase Bills. Original issuer requests with a reason; supervisors approve/reject. Preserve original bills/items/photos and audit every decision. Approved void reverses only an existing matching Cash Float deduction, exactly once. Keep completed stops completed. Reissue uses a new bill number linked to the approved void and current eligible product prices, with new Cash payment proof. Never delete the original bill or refund an amount without an original recorded deduction.

- Employee & Account directory: all eleven column menus use the same search, checkbox multi-select, Blank, Select all, ascending/descending, clear sort/filter and Close controls as the archives. Open one menu at a time. Unchecking all means no matches; clearing a filter restores all. Use actual records in the current employee group for options; preserve raw names/identifiers. Former employee dates show the latest employment period.

- Supervisor date requests: expand inline, edit date or retain it and change Route, and choose once-only (default) or permanent. Once-only changes appear as Customer Schedule exceptions; permanent changes update fixed weekdays/Route and reconcile this customer's generated future plans. Preserve executed/protected records and explicitly report their dates. Require an eligible assigned, unstarted target vehicle; expose date-specific routes and a planner entry for missing dates. Keep the original requested date, source stop and review audit.
