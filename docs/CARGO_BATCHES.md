# 货物批次第一版

入口：员工手机 More → 货物批次。司机的 Weight 页面也可以开始本批收货。

- 新趟次经现有出车审批后开始：若车上没有未完成批次，生成 H 开头的批次号，记录原司机。已有未卸完批次则保留原号和原人员。
- 上线时已经运行的趟次：司机在货物批次页面选择「开始本批收货」。不会自动重建历史人员或单据。
- Attendant 输入号码核对车牌、司机和收货日期，再确认参与。本版只允许派车名单内的 attendant 加入今天开始的批次；已关闭批次不能新增参与者。
- 确认磅单重量时选择批次、填写工厂下货单号码，并选择部分卸货、全部卸完，或补交旧批次单据。
- 全部卸完：一次性关闭批次并准备新号码。新号码不带收货人员，下一次开始收货时再确认司机。部分卸货不换号，补交旧单不影响当前批次。
- 新号码通过手机页面顶部提示，保存到服务器；页面打开时每 10 秒检查，也会在卸货保存后立即检查。不发送 WhatsApp、短信或浏览器关闭时的后台推送。
- 双方在货物批次页面查看参与记录；换设备仍能看到。同一天或隔夜由另一司机卸货，原批次成员保持不变，上传人另存。
- 旧客户端的历史磅单仅在车辆尚未采用批次时维持原确认流程。车辆一旦有批次，确认新磅单必须关联批次。已确认的旧记录不会被自动关联。

本版不计算员工结算重量或报酬，也不自动匹配卖货单。不支持混批、转车或修改已确认参与者；这些后续另行设计。磅单原记录上的司机/crew快照仍保留其既有含义，原收货人员以批次成员记录为准。

数据库升级 70 → 71，仅添加四张表和索引/保护触发器，不改旧磅单字段。
部署：scripts/apply-cargo-batches-production.sh。先构建，再停服务备份，启动执行迁移，校验 schema、完整性、外键和健康状态，最后替换前端。失败恢复前版代码及前端，保留已产生的数据。
