# 员工累计重量与所得

入口：Owner 工作台「员工累计重量与所得」；员工手机底部「收入」。手机默认显示本期和上一期，选择日期可查历史。打开页面每30秒更新；这不是关闭浏览器后的推送。

## 期间与重量

货物批次 collection_date 决定所属期间。1–15号对应20号；16号到月底对应次月5号。延迟下货、下一期才收到结算单，仍回填原批次期间。跨日持续装货的批次目前沿用开始收货日期，拆分跨期批次需要后续业务规则，不能用到账日代替收货日期。

按原 cargo_batch_members 中已确认人员计算，不能按送货当天的新司机/跟车员替换。两名attendant各得到完整参与重量×0.03，公司重量每张单只算一次。未确认批次参与的员工不会凭名字或当天派车推算收入。

以车牌对应的 vehicle_id、去首尾空格且不区分大小写的工厂下货单号码、送货日期查找卖货单明细。两边都唯一匹配才使用卖货单 weightKg；日期不符、车牌修正与原批次矛盾、多候选、重复下货单均列为待对账。匹配是实时核对，并非已经完成转账。旧单没有批次的数量单独显示；不猜历史人员归属。当前版本未提供旧单批次补关联或歧义人工消解入口，需后续处理，不能将待对账工资算作零后发款。

司机默认档位：0、25000、27500.001、30000、34500.001、40000kg起分别RM.030/.040/.043/.045/.047/.050；重量精度0.001kg。全部司机重量乘达到的单价；每位attendant独立固定RM.030。所得以整数精度运算四舍五入到分；同时担任两种身份时分别累计对应身份重量，再合计金额。

## 权限与历史

公司汇总、设置及已发款操作仅owner_admin；每个员工用session employeeId读取自己，查询参数不能选择别人。管理人员的员工预览未开放所得接口，避免绕过薪酬权限。

工资设置追加不可变版本，须从本期或以后1号/16号生效；拒绝旧版本覆盖、重复/逆序档位、递减或非法单价。会影响已发款期间的设置不能保存。报表读取适用版本；仅手动确认员工已收到款项后保存该员工完整快照。期间尚未结束、有待对账/未关联旧单或无应付金额都不允许确认。重复提交不会重复记款。之后源单变化会提示核对，已发款快照金额不变，不自动补扣款、不写现金账。

## 通知与部署

每天马来西亚时间午夜后生成个人KCS系统内通知。后台每30秒检查Kuching日期，正常运行时00:00后30秒内生成；程序重启会补生成当天缺失通知，不伪造停机期间的历史快照。通知用实际生成时间标示，保留当时所得和待对账重量；下面报表继续显示最新对账结果。每人每天一次，跨进程/重启不重复，失败整批回滚后自动重试。员工关闭页面也保留通知，打开后收入底部入口显示未读数；不是系统外推送。1号/16号通知包含昨天所在半月，保留刚结束期间的所得。默认查看今天的页面跨午夜自动换日，主动选中的历史日期保留。薪酬通知独立于普通公告，普通公告管理/员工预览不能读其他人的所得。

迁移72只新增earnings_rules和earnings_payments及不可变触发器，不改写业务历史。使用scripts/apply-earnings-production.sh，支持从70/71/72进入，先构建、停API备份SQLite与前端、启动迁移、校验后替换前端；失败恢复此前代码与前端，保留数据库新增记录。

通知升级使用 scripts/apply-income-notifications-production.sh，迁移73新增个人每日收入通知表及唯一键/不可变快照保护，兼容从70/71/72/73部署。员工可逐条确认已读，未读优先显示最近60条，读后可继续处理更早的未读通知。
